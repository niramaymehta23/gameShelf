# Our Game Shelf

Connect Four and Battleships for two, played on two phones wherever you both are.
One of you sets up a table and sends the invite; the other joins with the four-letter code.
Rock, paper, scissors decides who goes first. A short how-to-play card opens every new game,
games can be saved and carried on later, and you can send each other quick reactions and notes.

It's a static site on Firebase Hosting. Games are stored in Firestore and kept in sync live;
who's at the table (and where their finger is) goes through the Realtime Database.
There is no build step.

## Run it on your computer

Needs Node 20 or newer and Java 11 or newer (for the Firebase emulators).

```bash
npm install
npm start
```

That runs the Firebase emulators locally, so nothing touches the real project. Open
http://localhost:3000. To play both sides on one computer, open a second tab at
http://localhost:3000/?as=2. Local game data is thrown away when you stop it.

To try it on your phone over the same Wi-Fi, find your computer's local IP
(on a Mac: `ipconfig getifaddr en0`) and open `http://<that-ip>:3000` on the phone.
Sharing, copying the invite link and keeping the screen awake need HTTPS, so they work fully
on the deployed site.

## Put it online

Live at **https://gameshelf-ee306.web.app** (Firebase project `gameshelf-ee306`, pay-as-you-go Blaze plan;
two people playing stays inside the free quota).

```bash
npx firebase login
npm run deploy        # hosting + Firestore rules + Realtime Database rules
```

The project is set in `.firebaserc`. Deploying writes the web settings into
`public/js/firebase-config.js` first (git-ignored; see Security). Copy `.env.example` to `.env`
and fill in the App Check site key before your first deploy from a new machine.

Then open the site on both phones and use **Add to Home Screen** (Safari share menu on iPhone,
the ⋮ menu in Chrome on Android). It launches full-screen like an app.

## Security

- **No keys or settings in the repo.** `public/js/firebase-config.js` is generated by
  `tools/firebase-config.mjs` right before each deploy (from your logged-in Firebase CLI and `.env`)
  and is git-ignored. Locally it's a placeholder, because the emulators need no real settings.
- **The API key only works from the site.** Visitors' browsers still receive the Firebase settings (every
  Firebase web app works this way), so the browser key is restricted in Google Cloud Console → APIs & Services
  → Credentials to `https://gameshelf-ee306.web.app/*` and `https://gameshelf-ee306.firebaseapp.com/*`.
- **App Check** (reCAPTCHA Enterprise) is enforced on Firestore and the Realtime Database, so they only
  answer requests from the real site, not scripts or copies of it. The site key goes in `.env`
  as `APPCHECK_SITE_KEY` (see `.env.example`).
- **Rules guard the data** (`firestore.rules`, `database.rules.json`): only table and match documents with
  valid codes can be touched, tables can't be listed, and presence entries are validated. Anyone at the
  table (who knows its four-letter code) can play there; that's the intended trust model.
- Firebase CLI login lives on your machine (`npx firebase login`), never in the repo.
- GitHub secret scanning, push protection and Dependabot alerts are on.
