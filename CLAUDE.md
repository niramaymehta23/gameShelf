# Our Game Shelf — guide for Claude Code

Two-player board games (Connect Four, Battleships; Guess Who? planned) that Niramay plays with his
partner on two phones in two different places (his Android, her iPhone). Someone sets up a table,
gets a four-letter code, the other joins with it. Rock-paper-scissors (best of three) decides who
starts each game. Everything is **touch-first**: no hover states, big targets, drag/tap/swipe.

It started as a Claude artifact and was ported to this standalone app. The look ("watercolour on a
linen tablecloth") is deliberate and hand-made; keep it.

## Commands

```bash
npm install                 # firebase-tools + playwright (dev only; the site has no npm deps)
npm start                   # Firebase emulators: http://localhost:3000 (hosting), 8080 firestore, 9000 rtdb; data not kept
npm run check               # syntax-check every client file
npm test                    # = test:e2e
npm run test:e2e            # emulators + two browser "phones" play full games of both; needs: npx playwright install chromium
HEADED=1 npm run test:e2e   # watch it play
npm run deploy              # hosting + firestore rules + database rules to the real project (needs firebase login)
```

Before saying a change works: `npm run check && npm test` must both pass, and look at
the screenshots in `tests/e2e/screens/` for anything you touched visually.

Two players on one computer: open `http://localhost:3000` and `http://localhost:3000/?as=2`
(the `as` parameter gives the tab its own device identity). Phones on the same Wi-Fi can use
`http://<your-mac's-LAN-IP>:3000`, but clipboard, share sheet and screen wake-lock need HTTPS,
so they only fully work once deployed. `net.js` uses the emulators (project `demo-gameshelf`)
whenever the page is on localhost or a private LAN address, and `FIREBASE_CONFIG` otherwise.

## Layout

```
firebase.json          Hosting, rules files, emulator ports.
firestore.rules        Who may read/write tables and matches (paths only; same trust model as before).
database.rules.json    Realtime Database rules for presence/{CODE}/{id}.
public/index.html      Shell + script order (Firebase compat SDK from gstatic, pinned, first).
public/css/app.css     All styles. Design tokens in the first :root block.
public/js/             Classic scripts sharing globals, loaded IN THIS ORDER:
  util.js              h() DOM helper, sleep/settle, icons, Sound (WebAudio synth, no files)
  firebase-config.js   FIREBASE_CONFIG for the deployed project
  net.js               FB (Firebase init), Pref (localStorage), Net (Firestore document API), Live (RTDB presence)
  app.js               G (app state), write(), table/match lifecycle, toast, sheet, router, top bar
  lobby.js             Screens: landing, seat, waiting, shelf, match shell; GAMES registry; end sheet
  rps.js               rpsState() + the who-goes-first phase
  connect4.js          c4State() + the board
  battleships.js       bsState(), fleet placement, battle
  boot.js              start-up, invite links (?join=CODE)
public/art/            Painted textures and illustrations (generated by tools/paint_art.py)
public/icons/          Home-screen icons (tools/make_icons.py)
tests/e2e/             two-players.mjs (Playwright, run against the emulators)
```

No bundler, no framework, no build step. Keep it that way unless there's a strong reason.

## How sync works (read before touching game logic)

- Two kinds of Firestore document, enforced by `firestore.rules`:
  - `tables/{CODE}` → `{ code, created, host:{dev,name}, guest:{dev,name}|null, current: matchId|null, results: {matchId:{g,w}} }`
  - `tables/{CODE}/matches/{id}` → `{ id, game:'c4'|'bs', by, created, rps:{r1:{host,guest},…}, moves:{m000:col,…}, shots:{s000:{r,c},…}, fleets:{host:[…]|null, guest:[…]|null} }`
- **Moves are an append-only log.** Each move is written under its own zero-padded key (`m007`,
  `s012`) with `update` (deep merge: `Net` turns nested objects into dotted field paths), so two
  phones never overwrite each other. Firestore forbids arrays inside arrays; keep data shapes flat. The board is
  always *derived* by replaying the log in key order: `rpsState(m)`, `c4State(m)`, `bsState(m)`
  are pure functions and the only source of truth for turn, winner, hits, etc. Both screens run
  the same replay, so they always agree. Never store derived state (whose turn, winner) in a document.
- Seats are `host` / `guest`. A phone's seat is found by matching its device id (`G.dev`, kept
  in localStorage) against `table.host.dev` / `table.guest.dev`.
- `Net.doc(path).onSnapshot()` subscribes to the Firestore document. Your own writes show up
  immediately (latency compensation), before the server confirms. The SDK reconnects by itself;
  `Net.online` follows the Realtime Database connection. Requests give up after 15 s.
- `Live` is presence only, in the Realtime Database at `presence/{CODE}/{pushId}` with
  `onDisconnect().remove()`: `{seat, screen, hover, aim}` so you can see your partner's disc hovering
  over a column or their crosshair on your fleet. Never put game state there. New keys need a line
  in `database.rules.json`.
- A game screen re-renders from `G.match` in `update(m)`; animations queue behind each other
  (`rendered` counter vs log length). Use `settle(anim)` rather than awaiting `anim.finished`
  directly, so a backgrounded phone with paused animations can't wedge the game.

## Design system (keep the look)

Game night on a blue linen tablecloth. Everything is a physical object on the table.

- Materials: `.paper` (watercolour paper card) + `.tape` (washi tape, `.sage`/`.rose` variants),
  `.sage-wood` (the painted dresser), the milk-painted blue Connect Four frame (`--t-blue`),
  the sea chart (`--t-sea`), weathered hulls (`--t-hull`). Textures are tokens `--t-*` in app.css.
- Painted art (`public/art/*.png`) is watercolour with transparency, drawn with
  `mix-blend-mode: multiply` (class `.wc`) over paper so it reads as paint, not stickers.
- Type: Caprasimo (display, titles), Caveat (handwriting: status lines, notes, scores),
  Figtree (UI: buttons, labels). Status/feedback text is handwritten (`.status-line`, `.hand-note`).
- Colour: linen `--linen`, ink `--ink`, poppy red `--poppy` (primary action, red discs, hits),
  ochre `--ochre` (selection, aim, yellow discs), navy `--navy`, sage `--sage`.
- Slight rotations on cards (±0.5–1.5°) are intentional. Don't "fix" them.
- Don't introduce generic UI: no gradient washes, glassmorphism, emoji, default shadows on
  everything, or system-looking cards. New screens should be built from the same materials.
- Touch rules: targets ≥ 44 px, no hover-only affordances, `touch-action: none` on boards that
  drag, `pointer*` events (not mouse/touch), and test at 390×844.

Regenerating art: `python3 tools/paint_art.py` (numpy, scipy, Pillow) writes to `public/art/`;
`python3 tools/make_icons.py` rebuilds icons. The art is procedural, so tweak the script, not the PNGs.

## Gotchas

- `connect4.js`: `pending` (my move sent, not yet confirmed) is cleared as soon as the snapshot echo (Firestore echoes local writes at once)
  arrives, so a player can aim while the last disc is still falling. Don't gate input on `animating`.
- `battleships.js`: firing *is* gated on `animating` so shots resolve one at a time.
- The status line has a fixed height so taps on the chart don't land on the wrong square when the
  text wraps. Keep `.status-line { min-height }`.
- iOS: no `navigator.vibrate`; WebAudio only starts after a tap (handled in `Sound.ensure`);
  safe-area padding lives on `:root`.
- Firebase trusts clients (it's for two people): anyone with a table code can read and write it.
  Secrets are visible to a curious partner with dev tools: RPS picks before the reveal and the
  opponent's fleet. See roadmap.
- Old tables are not cleaned up automatically (the old server pruned after 30 days). They're tiny.
