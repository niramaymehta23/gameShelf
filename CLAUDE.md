# Our Game Shelf — guide for Claude Code

Two-player games (Connect Four, Battleships, Word Wheel, and our own Hues, Quickfire and Sharp Wits) that Niramay plays with his
partner on two phones in two different places (his Android, her iPhone). Someone sets up a table,
gets a four-letter code, the other joins with it. Rock-paper-scissors (best of three) decides who
starts each game. For practice alone there's Otto, the bot (`bot.js`): a solo table where he takes
the other seat on this phone. Everything is **touch-first**: no hover states, big targets, drag/tap/swipe.

It started as a Claude artifact and was ported to this standalone app. The look ("watercolour on a
linen tablecloth") is deliberate and hand-made; keep it.

## Commands

```bash
npm install                 # firebase-tools + playwright (dev only; the site has no npm deps)
npm start                   # Firebase emulators: http://localhost:3000 (hosting), 8080 firestore, 9000 rtdb; data not kept
npm run check               # syntax-check every client file
npm test                    # = test:unit (incl. the golden replay check) + test:e2e
npm run test:e2e            # emulators + two browser "phones" play full games of each; needs: npx playwright install chromium
HEADED=1 npm run test:e2e   # watch it play
npm run deploy              # hosting + rules to gameshelf-ee306 → https://gameshelf-ee306.web.app (needs: npx firebase login)
E2E_URL=https://gameshelf-ee306.web.app node tests/e2e/two-players.mjs   # same test against the live site (leaves a table; delete it)
```

Before saying a change works: `npm run check && npm test` must both pass, and look at
the screenshots in `tests/e2e/screens/` for anything you touched visually. A CSS change meant to look
the same can be proved with `tests/visual/compare.mjs` (see its header): DOM snapshots from an e2e run
(`CAPTURE=<dir> npm run test:e2e`), drawn with the old and new app.css, must match in every computed
style and pixel at 390×844, 320×640 and 1280×800.

Two players on one computer: open `http://localhost:3000` and `http://localhost:3000/?as=2`
(the `as` parameter gives the tab its own device identity). Phones on the same Wi-Fi can use
`http://<your-mac's-LAN-IP>:3000`, but clipboard, share sheet and screen wake-lock need HTTPS,
so they only fully work once deployed. `net.js` uses the emulators (project `demo-gameshelf`)
whenever the page is on localhost or a private LAN address, and `FIREBASE_CONFIG` otherwise.

## How sync works (read before touching game logic)

- Two kinds of Firestore document, enforced by `firestore.rules`:
  - `tables/{CODE}` → `{ code, created, host:{dev,name}, guest:{dev,name}|null, current: matchId|null, results: {matchId:{g,w,at}}, saved: {c4: matchId|null, bs: …}, notice: {id, by, kind, game, match} }`
  - `tables/{CODE}/matches/{id}` → `{ id, game:'c4'|'bs'|'hu'|'qf'|'ww'|'sl'|'sw', by, created, seed, hueVersion?, hueRules?, rps:{r1:{host,guest},…}, moves:{m000:col,…}, shots:{s000:{r,c},…}, plays:{p0000:{by,k,id?,col?},…}, fleets:{host:[…]|null, guest:[…]|null}, qf:{by,mode,len,side,op}, picks:{r001:{host,guest}}, ans:{r001h:{w|n,ms}|{out,ms}|{pass,ms}}, ww:{by,n}, finds:{f000:{by,w}}, sw:{by,g}, laps:{h000:{n,ms,x,k?}|{end,ms,x}, g000:…}, joined:{host,guest}, quit:{host,guest} }`
- **Opening, saving, quitting** (app.js, "opening, joining, saving and quitting games"): whoever opens a game
  is in it; the other phone gets a Join / Not now sheet (`joined`, missing map = both in). Leaving a game with
  progress offers Save and quit / Quit without saving. Either player saving keeps it in `saved[game]`; one quit
  only pauses it (still in `saved`) and the other phone must choose Keep it saved / Quit too; both quitting
  clears it. `notice` tells the other phone what happened (shown once per phone, except a pending quit).
  Starting a new game of a kind replaces that kind's saved game; finishing a saved game clears it.
- **Moves are an append-only log.** Each move is written under its own zero-padded key (`m007`,
  `s012`) with `update` (deep merge: `Net` turns nested objects into dotted field paths), so two
  phones never overwrite each other. Firestore forbids arrays inside arrays; keep data shapes flat. The board is
  always *derived* by replaying the log in key order: `rpsState(m)`, `c4State(m)`, `bsState(m)`,
  `huState(m)`, `qfState(m)`, `wwState(m)`, `swState(m)` are pure functions and the only source of truth for turn, winner, hits, etc. Both screens run
  the same replay, so they always agree. Never store derived state (whose turn, winner) in a document.
  `tests/unit/replay.mjs` checks every replay function against golden results for a few hundred seeded
  documents; only rewrite them (`node tests/unit/replay.mjs --write`) when a replay change is intended.
- Seats are `host` / `guest`. A phone's seat is found by matching its device id (`G.dev`, kept
  in localStorage) against `table.host.dev` / `table.guest.dev`. Names belong to the seat and can change
  (`renameSeat`: the shelf's "Change my name", or joining again by code with another name typed); only
  `{seat}.name` is written, never `dev`. The other phone gets a toast.
- **Stats** (`stats.js`): `tableStats(table, matches)` replays every finished game (`table.results` and
  its match document) with the games' own replay functions: wins, streaks, the log, RPS habits and each
  game's records. Nothing derived is stored, and games from before stats existed count. The rules allow
  `get` but not `list` on matches, so `loadTableStats()` fetches them by id (results, saved, current).
  A new record is a few lines in `STATS_GAME[game]` plus a row in `statsView()`.
- `Net.doc(path).onSnapshot()` subscribes to the Firestore document. Your own writes show up
  immediately (latency compensation), before the server confirms. The SDK reconnects by itself;
  `Net.online` follows the Realtime Database connection. Requests give up after 15 s.
- **Chat** (`Chat` in net.js, UI in app.js "chat"): Realtime Database `chat/{CODE}/{pushId}` =
  `{seat, e | t, at}` — one emoji (`CHAT_EMOJI`) or a note of ≤ 80 characters, validated in
  `database.rules.json`. Messages already there when a table opens are history (thread only, no pop-up).
  Old ones (> 24 h) are pruned on join. Incoming emoji burst under the partner chip (`#chatfx`); notes
  join the toast stack. Talk only: never put game state in chat.
- **How to play**: `GAMES[key].howTo` (lobby.js) is the one source of rules (for Hues, `hueRuleSteps(m)` in hues.js;
  `GAMES.hu.howTo` is only shown for saved version-1 games): the 'howto' phase before
  every new game (skippable per game via `Pref howto-skip:<game>`), the ? in the game header, and the shelf sheet.
- **Otto, the bot** (`bot.js`): *Play Otto, the bot* on the landing page creates an ordinary table with
  `guest: {dev:'bot', name:'Otto', bot:true}` (`isBotTable()`, `botSeatOf(t)`). Otto runs on this phone and
  writes his moves under his own seat into the same logs (plain `write`s, or transactions re-checked like the
  screen's), so every replay, screen and the stats work unchanged. His table is its own table, so its score and
  stats never mix with the shared one. Easy or Hard is picked when a game is opened (`startMatch(game, level)`,
  kept as `match.bot`; a rematch keeps it). He's in from the start (`joined` both true) and games against him
  aren't saved: leaving one with progress offers only *Quit the game* (`quitBotGame`). No chat button there.
  `Bot.sync()` runs after every `route()`: it starts a controller for the current match and stops it when the
  match is put away. Before the RPS is decided Otto throws (`botRPS`); after it, the game's bot gets
  `update(m)` on every snapshot and poke (phase change, page shown). The `ctx` it gets: `seat`, `level`/`hard`,
  `rng`, `m()` (latest match or null once stale), `ready()` (this match's game phase is on screen and the page is
  visible: Otto only moves then), `phase()` (`G.phase`, set by the match shell), `plan(key, ms, fn)` (one timer
  per key; waits for `ready()` unless `{needReady:false}`), `later`, `write(patch)`, `tx(latest => patch)`,
  `choose(field, value)` (the RPS winner's one choice, like `chooseOnce`) and `show({hover}|{aim})`, which feeds
  `Live.partner()`: at Otto's table it returns a made-up peer on your screen, so the green dot, "Otto is lining
  up a move…", the partner ghost disc and his crosshair all work. What Otto would do is a pure function per game
  (`c4BotMove`, `bsBotShot`, `huBotTurn`/`huBotColour`/`huBotCatch`, `qfBotSetup`/`qfBotPick`/`qfBotPlan`/`qfBotMove`,
  `wwBotWord`, `slBotPlay`, `swBotRun`), each tested in `tests/unit/bot-<game>.mjs`; the controllers only add timing.
- `Live` is presence only, in the Realtime Database at `presence/{CODE}/{pushId}` with
  `onDisconnect().remove()`: `{pres: {seat, screen, hover, aim}, at}` so you can see your partner's disc hovering
  over a column or their crosshair on your fleet. Never put game state there. New keys need a line
  in `database.rules.json`.
- A game screen re-renders from `G.match` in `update(m)`; animations queue behind each other
  (`rendered` counter vs log length). Use `settle(anim)` rather than awaiting `anim.finished`
  directly, so a backgrounded phone with paused animations can't wedge the game.

## Design system (keep the look)

Game night on a blue linen tablecloth. Everything is a physical object on the table.

- Materials: `.paper` (watercolour paper card) + `.tape` (washi tape, `.sage`/`.rose` variants),
  `.sage-wood` (the painted dresser), the milk-painted blue Connect Four frame (`--t-blue`),
  the sea chart (`--t-sea`), weathered hulls (`--t-hull`). Textures are tokens `--t-*` in app.css.
- Painted art (`public/art/*.png`) is watercolour with transparency, drawn with
  `mix-blend-mode: multiply` (class `.wc`) over paper so it reads as paint, not stickers.
- Type: Caprasimo (display, titles), Caveat (handwriting: status lines, notes, scores),
  Figtree (UI: buttons, labels). Status/feedback text is handwritten (`.status-line`, `.hand-note`).
- Colour: linen `--linen`, ink `--ink`, poppy red `--poppy` (primary action, red discs, hits),
  ochre `--ochre` (selection, aim, yellow discs), navy `--navy`, sage `--sage`.
- Slight rotations on cards (±0.5–1.5°) are intentional. Don't "fix" them.
- Don't introduce generic UI: no gradient washes, glassmorphism, emoji, default shadows on
  everything, or system-looking cards. No pill shapes for labels, status or chips (Niramay finds them
  "vibe coded"); use paper, tape, small caps and handwriting instead. Emoji appear only as chat reactions.
  Header buttons are all `.icon-btn` (42 px), two each side, so the title stays centred. New screens should be built from the same materials.
- Touch rules: targets ≥ 44 px, no hover-only affordances, `touch-action: none` on boards that
  drag, `pointer*` events (not mouse/touch), and test at 390×844.

Regenerating art: `python3 tools/paint_art.py` (numpy, scipy, Pillow) writes to `public/art/`;
`python3 tools/make_icons.py` rebuilds icons. The art is procedural, so tweak the script, not the PNGs.

## Gotchas

- `connect4.js`: `pending` (my move sent, not yet confirmed) is cleared as soon as the snapshot echo (Firestore echoes local writes at once)
  arrives, so a player can aim while the last disc is still falling. Don't gate input on `animating`.
- `battleships.js`: firing *is* gated on `animating` so shots resolve one at a time.
  House rule `HIT_AGAIN`: a hit earns another shot, so the same player can fire many times in a row
  (the e2e `shoot()` waits for "Tap a square" in the status, not just the button text). Hits are
  burning pegs (CSS flame + smoke), misses are white flags (inline SVG, cloth waves via SMIL).
- `hues.js` (Hues, house rules from Niramay's spec, our own deck and card names): 95 cards, per
  colour (lavender, orange, navy, sage) 1–9 twice, 2 Again (go again), 2 Splash (+2); then 4 Blend
  (wild), 2 Flood (+4, wild), 1 Trade (swap hands, wild). Deal 7, at most 2 action cards per opening
  hand (Niramay found more unbalanced); the pile starts on a number. The shuffle is uniform (checked
  with chi-square), so balance changes belong in the deck mix or the deal, not the RNG.
  Both phones shuffle the same deck from `match.seed` (`hueRng`), and reshuffle the pile the same way
  when the deck runs out. **Two versions**: new matches have `hueVersion: 2` and `hueRules`
  ('custom' | 'official', chosen once by the RPS winner, see docs/hues-rules.md); `plays` keys are five
  digits (`p00042`), each command is appended in a transaction checked with `hueApply`, carries `at`
  (client time, or a server timestamp for ordinary moves), and the commands include `notice` (this phone
  showed the turn: the two-second call-out lockout starts) and `shuffle` (Custom: twice each). Saved
  version-1 games (no `hueVersion`) replay with `huLegacyState`: four digits plus the seat (`p0042h`).
  Moves that don't count (wrong seat, card doesn't fit `hueFitsAll`) are skipped by the replay.
  Same-number cards can go down together (`ids`, last one sets the colour). Penalties stack without
  limit (+2 on +2, a Flood on anything, +2 on a Flood only in its named colour); whoever takes them
  then plays or passes (`paid`). One card left without calling Hues (`owes`) can be called out until
  that player's next turn: +2 cards. Winning waits for the chain; in version 1 also for the turn owed after
  taking one (`grace`), in version 2 the game ends as soon as the chain is picked up. Unplayable cards are NOT dimmed (Niramay's call): a wrong card is refused with a
  note. Input is gated on `animating`. Cards are HTML on painted panels (`art/hue-*.png`).
- `quickfire.js` (Quickfire, our own: two races in one box). The RPS winner sets it once (`match.qf`): Mixed
  (first to 10, Words or Sums per round drawn from `match.seed`), Words or Sums (first to 5); word length 4/5/6
  and whether their letter is the first or last; add/subtract (1–100) or multiply (0–30). Each round both pick
  in secret (`picks`), like RPS. **Timing is per phone**: an answer's `ms` is measured on the answering phone
  from when the puzzle appeared on *its* screen (clock waits while the page is hidden; start kept in Pref so a
  reload doesn't reset it), so lag costs nobody and no clocks need to agree. Fastest right answer wins. A phone
  that sees the other's right answer at t ms keeps its player racing until its own clock passes t, then writes
  `{out}`; the round settles only then. Equal ms is a dead heat (no point). `{pass}` gives up (sent for you after
  `QF_LIMIT`); both passing scores nobody. An answer sends itself once it's long enough (the
  middle letters; as many digits as the sum's answer, so 3 digits for 120). Wrong words/sums are refused on
  the phone, never written, and cleared so you can go again at once (no lockout). Picks keep Lock in
  (a Sums pick could be 1, 10 or 100); every submit button is disabled while nothing is typed. A letter pair with no everyday word (`qfFits`) is void and re-picked.
  Subtract is always bigger minus smaller. Never show the other's answer before your round settles (it would
  give it away). Keyboard: one `<input>` for both picking the letter and typing the word, kept focused across
  rounds (buttons `preventDefault` on mousedown and refocus on click), because iOS only raises the keyboard from
  a tap; Sums use the app's own keypad (no OS keyboard switching mid-game). The phase's `relayout()` is a no-op:
  the keyboard resizing the window must not rebuild it. `QFViewport` follows `visualViewport` (`body.kb-open`,
  `--vvh`) so the tiles, clock and status stay above the keyboard. Regenerate the dictionary with
  `python3 tools/make_words.py enable1.txt count_1w.txt` (offensive words are kept out of the everyday list).
- `wordwheel.js` (Word Wheel, our own take on the newspaper puzzle, with no middle letter: nine letters on a ring,
  any word of four or more of them, a letter used as often as it's on the wheel). The RPS winner spins once: `match.ww = {by, n}`, `n` from
  `wwPick(code, finished)`, a per-table order of all 100 wheels, so a table sees each once before repeats. Each player
  finds their own words (`found.host` / `found.guest`): both can find the same word, and the partner's words show as
  stars, one a letter, until the race is over (a peek with dev tools would show them; same trust model as above).
  Words are claimed by appending `finds.fNNN = {by, w}` in a transaction that re-checks `wwState`; the replay skips a
  player's repeats, words not in the wheel's list and anything after the winner. First to `WW_TO` (5). Short words,
  plurals, non-words and your own found words are refused on the phone and never written (a swipe can't pick a
  letter twice; the keyboard takes the next free copy of a letter). Swiping: letters are hit-tested in the wheel's own 0–100 box (`WW_HIT` is small
  enough to slide between two letters; moving back onto the previous letter removes the last one); a real
  keyboard types too. Shuffle only reorders letters on this phone. The partner's swipe is deliberately not in
  presence (it would give words away). Lists are ENABLE, so obscure words count; the wheels themselves are
  rebuilt with `python3 tools/make_wheels.py enable1.txt count_1w.txt` (seeded; it keeps the wheels already in
  wheels.js, letters and order, and only redoes their lists or appends new ones; `tests/unit/wordwheel-data.mjs`
  checks the rules and completeness against `QF_WORDS`). Changing or reordering `WW_WHEELS` changes saved and
  finished games' wheels: only append. Until Nov 2026 every word needed a middle letter (`{c, o}`); those wheels
  kept their letters and their lists only grew, so older games replay the same.
- `sharpwits.js` (Sharp Wits, our own box of eight quick brain races). The RPS winner picks one (`match.sw = {by, g}`,
  `chooseOnce`, the `sw-setup` phase): `spot` Odd One Out (two panels of scattered emoji, one above the other; tap what
  changed: another look-alike, mirrored, turned or resized; ten puzzles of 7–16 emoji, the last four with two changes),
  `copy` Copycat (seven dots scattered on paper flash in order, tap them back; level L is L + 2 dots, to 10 at level 8;
  one wrong tap is out), `ink` True Colours (tap the paint colour of a colour word, 20 cards) and `hunt` Number Hunt
  (1–25 in order on a 5×5 grid), `shade` Odd Shade (one square a shade off; 15 grids from 3×3 to 6×6, the lightness gap
  shrinking from 16 to about 5 points), `pairs` Pairs (16 cards face down, 8 pairs; a mismatch is a wrong tap and turns
  back when the lock ends), `way` Which Way (tap the way the middle of five arrows points; the others agree, disagree or
  are bars; 20 rows) and `flash` Flashback (level L lights L + 2 squares of a 5×5 grid; tap them in any order; levels
  and one-wrong-tap-out like Copycat). `SW_GAMES[g].levels` marks the level games (Copycat, Flashback: clock only while
  tapping, 'fail' allowed, a reload restarts the level); `keyed` marks Pairs, whose steps carry `k`, the pair found
  (the replay skips a step without a new valid k, and `run.keys` turns found pairs back up after a reload). Every
  puzzle is a pure function of `match.seed` (`swSpot`, `swCopy`, `swInks`, `swHunt`, `swShade`, `swPairs`, `swWays`,
  `swFlash`); nothing about them is stored. **Emoji are allowed here** (Niramay asked for them): Odd One Out's pieces
  only, single code points with no variation selectors (`SW_LOOKALIKES`); everything around them stays in the house style.
  **Timing is per phone**, as in Quickfire: each phone's clock starts at its own 3-2-1 Go and runs only while the page is
  showing (paused when hidden or the game is closed, saved in Pref `sw-clock:<id>` so a reload or a saved game carries
  on). Copycat's clock runs only while you tap, never while the dots play. Each phone appends only its own keys,
  `laps.hNNN` / `laps.gNNN` = `{n, ms, x}` (progress n reached at ms; x wrong taps so far) or `{end:'up'|'out'|'fail', ms, x}`,
  batched every 400 ms (an entry that could settle the race goes at once), so no transactions. The replay ignores a lap
  that skips a step, goes back in time or comes after the end; 'fail' only counts in the level games. Further beats less far;
  equal progress, the lower ms; equal both is a draw. Decided once both runs are over, or one is over and the other's
  progress already beats it (so a player who gave up at 5 loses the moment the other reaches 6). A phone whose partner
  finished everything writes `{end:'out'}` once its own clock passes the partner's time. A wrong tap locks the board
  for `SW_LOCK` ms (all but the level games). The e2e plays the first four from the shelf and the other four from
  ready-made match documents (RPS already won), to save time. Odd One Out hit-tests the nearest emoji in the panel's own 150×100 box (taps on
  empty paper are ignored); `.sw-e` has `pointer-events: none`, so the e2e clicks them with `force`. The race phase's
  `relayout()` is a no-op (rebuilding would restart the countdown). Box art is `box_sw` in `tools/paint_art.py`; the
  pieces are painted too (`sw_masks`, `sw_back`, `sw_symbols`): `art/sw-blob|swatch|ring|cross|arrow|bar.png` are
  near-black watercolour used as CSS `mask-image` and coloured by the page (dots, swatches, pencil rings, arrows), and
  `sw-back.png` / `sw-sym-0…7.png` are the Pairs cards. Grids lie on taped paper (`swSheet`), not the Connect Four board.
- Otto: his race clocks follow yours. Quickfire reads your screen's `qf-t0:<match>:<round>` start; Word Wheel and
  Sharp Wits count only while `ready()` and their phase is showing (Sharp Wits allows ~2 s for your 3-2-1).
  Sharp Wits runs are simulated up front (`swBotRun`: per-step times, wrong taps costing `SW_LOCK`, level games
  ending in 'fail') and each lap is written when his clock passes it; he writes `{end:'out'}` like a phone would.
  Hues: Otto plays only version-2 games, keeps the screen's command forms (`at`, `notice`, the 2 s call-out
  lockout), and on Easy forgets Hues about a third of the time. Battleships Hard hunts by counting the ways the
  ships afloat could lie (a sunk ship is shown to both players, so he may use its cells; he never reads your
  fleet otherwise). Connect Four Hard is a six-ply alpha-beta search. Easy is meant to be beatable while
  learning a game; Hard plays well but at a human pace. A new game needs `xxBot(ctx)` in its file, a line in
  `BOT_GAMES` and tests; Otto shouldn't need anything in `firestore.rules` (his writes are the same shapes).
- `el.replaceChildren(a, null)` / `append(null)` write the text "null" (unlike `h()`, which skips
  null kids): spread an empty array instead. The e2e `junk()` helper checks pages for undefined/null/NaN.
- The status line has a fixed height so taps on the chart don't land on the wrong square when the
  text wraps. Keep `.status-line { min-height }`.
- iOS: no `navigator.vibrate`; WebAudio only starts after a tap (handled in `Sound.ensure`);
  safe-area padding lives on `:root`.
- Firebase trusts clients (it's for two people): anyone with a table code can read and write it.
  Secrets are visible to a curious partner with dev tools: RPS picks before the reveal, the
  opponent's fleet, in Hues the other hand and the deck order, in Quickfire the other's pick before the reveal (and a cheat could fake their `ms`), in Word Wheel the other's words, in Sharp Wits every puzzle and answer (and a cheat could fake their `ms`) (`huState` deals both hands on
  every phone from the shared seed). See roadmap.
- Old tables are not cleaned up automatically (the old server pruned after 30 days). They're tiny.
